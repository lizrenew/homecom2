# 관심분야 자동 리서치 스킬

주제 하나를 받아 **근거를 직접 확인한 리서치 md**를 만들고 노션에 올린다.
확답하지 말고, 모든 내용은 실제로 확인한 출처에 근거해서 쓴다.

## 저장 위치

- 사용자가 폴더를 지정하면 그곳에 저장한다.
- 지정하지 않으면 주제와 관련된 기존 폴더를 찾아 그 안에 저장하고, 마땅한 폴더가 없으면 물어본다.
- 파일 이름: `research_<짧은주제>.md` (예: `research_타깃별_건강고민.md`)
- 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 먼저 물어본다.

## 절차

### ① 주제·키워드 묻기

AskUserQuestion으로 아래를 확인한다. 사용자가 이미 말한 항목은 다시 묻지 않는다.

- **주제**: 무엇을 리서치할지 (예: 필라테스 블로그 주제, 타깃별 건강 고민)
- **키워드**: 검색에 쓸 핵심 단어 2~5개
- **타깃·목적**: 누구를 위한 리서치인지, 결과를 어디에 쓸지 (예: 블로그 글, 상품 기획)
- **꼭 볼 출처**가 있는지 (예: 논문, 해외 인스타그램, 네이버 블로그)

### ② 브라우저 MCP로 사이트 3곳 이상 탐색

**Playwright MCP 브라우저**(`mcp__playwright__browser_*`)로 서로 다른 사이트를 **최소 3곳 이상** 직접 열어 확인한다.

추천 출처 조합 (주제에 맞게 고르기):

| 종류 | 사이트 | 용도 |
|---|---|---|
| 국가 통계 | 질병관리청, 통계청, 정책브리핑(korea.kr) 보도자료 원문 | 유병률·인구 등 수치 |
| 실제 고민 | 네이버 지식iN (`search.naver.com/search.naver?ssc=tab.kin.kqna&query=`) | 사람들이 실제로 쓰는 표현 |
| 경쟁·트렌드 | 네이버 블로그 (`ssc=tab.blog.all`), 네이버 플레이스 | 경쟁사 글 패턴, 업체 정보 |
| 해외 트렌드 | 구글 `site:instagram.com 키워드` | 해외 인스타그램 게시물 |
| 논문 | Europe PMC REST API, PubMed | 근거 강도 판정 |
| 책 | Open Library (`openlibrary.org/search.json?q=`) | 책이 실제로 있는지, 출판 정보 |

탐색 요령:
- 페이지 내용은 `browser_evaluate`로 `document.body.innerText`를 잘라 읽는다 (스냅샷보다 빠르다).
- 논문은 Europe PMC API가 안정적이다: `https://www.ebi.ac.uk/europepmc/webservices/rest/search?format=json&resultType=core&pageSize=3&query=<검색어>` → 제목·학술지·연도·초록·PMID 확인.
- **네이버 AI 브리핑이나 구글 AI 요약의 숫자는 그대로 쓰지 말고, 원문(보도자료·논문)을 열어 확인한다.**
- 책은 본문을 읽지 않았다면 "출판 정보만 확인"이라고 적는다.

막혔을 때:
- **"Browser is already in use"**: 다른 세션이 MCP 브라우저를 쓰는 중이다. 그 프로세스를 강제로 끄지 않는다. 잠시 뒤 다시 시도하거나, 사용자에게 알리고 별도 Playwright 스크립트(독립 브라우저)로 진행한다.
- **구글·DuckDuckGo·Bing 자동화 차단**: 네이버, Europe PMC, Open Library처럼 차단하지 않는 출처로 바꾼다.
- **PubMed 페이지가 로딩에서 멈춤**: 같은 논문을 Europe PMC로 확인한다.

### ③ md로 정리

아래 포맷을 그대로 쓴다. 판정 표시를 붙여서 근거의 강도를 구분한다.

```markdown
# [제목]
### [부제: 타깃 · 주제 한 줄]

---

## 수집일

[YYYY-MM-DD]

---

## 출처별 핵심

> 판정: ✅ 근거 있음 / 🔶 근거 제한적(조심해서 표현) / ❌ 근거 없음(주장하지 않기)
> 수집 방법: Playwright MCP 브라우저로 N곳 직접 확인([사이트 목록]) + [논문 DB] + [도서 DB]

### 1) [출처 묶음 이름]

| 출처 | 핵심 | 판정 |
|---|---|---|
| [출처명 (연도, 대상 n명)] | [수치 + 핵심 결과 1~2줄] | ✅ / 🔶 / ❌ |

### 2) [출처 묶음 이름]
...

---

## 한 줄 요약

**[리서치 전체를 한 문장으로: 핵심 발견 + 근거 있는 것 + 주장하면 안 되는 것]**

---

## 다음 액션

- [ ] [바로 할 일 (사용할 근거)]
- [ ] [추가로 찾아야 할 자료]
- [ ] [확인할 것]

---

### 참고 문헌 (PMID 또는 URL)

- [묶음]: [PMID, PMID, …]
```

작성 원칙:
- 숫자에는 **연도와 대상**을 함께 적는다 (예: "2024년 40대 남성 61.7%").
- 상관관계는 "관련이 있었다"로 쓰고, 인과관계처럼 쓰지 않는다.
- 오래된 자료나 작은 연구는 표에 그렇게 표시한다.
- 개인 연락처·이메일 같은 개인정보는 넣지 않는다.
- 확인하지 못한 것은 지어내지 말고 "확인 못 함"이라고 적는다.

### ④ 노션에 공유

1. **노션 커넥터 도구가 있으면**(ToolSearch로 `notion` 검색) 그 도구로 페이지를 만든다.
2. **커넥터가 없으면 MCP 브라우저로 올린다.**
   - `https://www.notion.so` 로 이동해 로그인 상태인지 확인한다. 로그인이 안 되어 있으면 로그인 화면만 열어 두고 사용자에게 직접 로그인해 달라고 한다. 비밀번호는 묻거나 입력하지 않는다.
   - 어느 페이지 아래에 올릴지 사용자가 말하지 않았으면, 개인 페이지(예: 메모)에 새 페이지로 만든다.
   - md 본문은 노션에 **붙여넣기 이벤트로 넣으면 표·체크박스·인용문이 자동 변환**된다. 보조 스크립트로 붙여넣기 코드를 만든다.
     ```bash
     node .claude/skills/research/scripts/make_notion_paste.js "<md 절대경로>" "<노션 부모 페이지 URL(선택)>"
     ```
     → `.playwright-mcp/notion_paste.js`가 만들어진다 (MCP가 읽을 수 있는 폴더). 그다음 실행한다.
     ```
     mcp__playwright__browser_run_code_unsafe(filename: ".playwright-mcp/notion_paste.js")
     ```
     부모 URL을 주지 않으면 현재 열려 있는 노션 페이지(데이터베이스)의 "새로 만들기"로 페이지를 만든다.
   - 결과로 나온 `tables= todos= hasSummary=` 값과 스크린샷으로 내용이 다 들어갔는지 확인한다.
   - 확인이 끝나면 `.playwright-mcp/notion_paste.js`를 지운다.
3. 공유 범위(공개 링크, 다른 사람 초대)는 사용자가 요청할 때만 바꾼다. 기본은 비공개다.

## 마무리 보고

- 저장한 md 파일 링크와 노션 페이지 URL
- MCP 브라우저로 확인한 사이트 목록 (3곳 이상인지)
- 한 줄 요약
- 확인하지 못한 것과 원문 확인이 더 필요한 숫자
